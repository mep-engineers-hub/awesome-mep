# Tier rules

> **Unverified. Not for stamped or issued work. Check against the adopted code edition.**

| Tier | Who can set it | Evidence required |
| --- | --- | --- |
| Found | Anyone | Link, license and a one-line description from public information. |
| Tried | A member who ran it | Entry file filled in: version, platform, what was run, what happened, known limits. |
| Validated against a worked example | A member who ran it, plus the PR reviewer | A published worked example (cite document, edition, clause # or the book/paper and page), the inputs used, expected vs tool results, and the difference. The comparison is linked from the entry. |

Rules:

1. A tier describes what one member did on one version. It is not a guarantee.
2. "Validated" never means code-compliant, certified, listed or approved.
3. If a newer version changes results, the entry drops back to Tried until re-checked.
4. Worked examples must be reproducible by others. Do not paste the example's tables or figures; cite them.
5. Anyone can challenge a tier by opening an issue with their own evidence.
